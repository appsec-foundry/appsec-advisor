## RC-D implementation plan (MR-16)

- `DiscoveryBudget` (`runtime/multi_repo_discovery.py`): a lock and condition guard `calls`, `spent_usd` and an in-flight count. `failed` becomes "a call is in flight or a cost is unsettled", which the checkpoint persists as unavailable accounting exactly as today; the retry and replacement decisions (`invoke`, `AssessmentJobs.exchange`) read only the unsettled part, otherwise a concurrent call would block every retry. A call whose ceiling exceeds the budget left after running reservations waits for a settlement while others run; with none running, today's smaller ceiling or exhaustion applies. The per-call reservation used by the timeout retry becomes thread-local.
- `AssessmentJobs` (`runtime/assessment_jobs.py`): checkpoint writes, `timing` and the inherited-receipt charge run under a lock; each component works on a child view with its own `notes` and `gaps`, joined in component order.
- `_assessment_stride` (`orchestrator/orchestration_controller.py`): the per-component body (targets, STRIDE jobs, evidence review) moves into a function run by a pool of four workers; documents, reviews and notes are collected by component position. The first failure stops new submissions through `should_stop`, waits for running jobs and re-raises, so resume keeps every accepted receipt.
- Host event files are numbered by a shared `itertools.count` (`_assessment_cli_host_factory`), which stays unique across threads.

## Deferred: repositories by Git URL

Proposed 2026-10-15, deferred by the operator until the controller items above are done. `run-headless.sh --repo <url>` would clone first and then assess the checkout like a local one, including the untrusted-mode preflight for repository-owned Claude configuration.

- **Reuse:** `analyzers/security_score.py` already clones safely: HTTPS only, normalized URL, ambiguous paths rejected, `core.hooksPath=/dev/null`, `http.followRedirects=false`, `--depth 1 --single-branch`, `GIT_LFS_SKIP_SMUDGE=1`, `GIT_TERMINAL_PROMPT=0`, timeout.
- **Decisions needed before work:**
  1. Requirement wording: REQ-PUR-003 covers selected repositories and the multi-repository plan lists remote cloning as later work, so URL input changes the product promise; propose the wording for confirmation.
  2. Private repositories: HTTPS through the user's existing Git credential helper, SSH URLs too, or neither. Always reject URLs with embedded credentials, which would otherwise reach logs and the report.
  3. Internal hosts: the existing path skips the IP check (`check_ip_safety=False`); allow internal hosts always, only behind an explicit option, or never.
  4. Revision and resume: MR-4 requires an unchanged source state, so pin the clone to a commit (`--ref` or the cloned head), record it as the source revision, and keep it in a stable cache directory so `--resume` and later runs reuse it.
  5. Output: require an explicit `--output`; MR-6 output inside a temporary checkout makes no sense.
- **Tests (aiscb):** rejected `file://`, `ext::` and `git://` schemes; URLs with credentials; redirects; submodules never fetched; plus the accepted HTTPS case and a pinned-revision resume.
