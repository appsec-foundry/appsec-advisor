# MCP clients, servers and proxies

Apply this lens to evidenced runtime MCP operations independently of LLM use. Establish client, server or proxy role, actual transport, initiating identity and downstream resource. Developer configuration belongs to the workstation supply-chain surface. A remote URL, package declaration or MCP name alone proves neither automatic approval nor a vulnerability. Never start a server, install a package, call a tool or follow discovery URLs to inspect it.

| Signal and trigger | Inspect and required evidence | Exclusions and classification |
|---|---|---|
| Protected HTTP MCP requests | Trace issuer/audience/expiry/scope validation, resource authorization, incoming versus downstream credentials, and owner binding of session/task handles. Cite receiving middleware and operation/resource checks. | A session handle is not authentication. A verified upstream enforcement point may satisfy a check. Do not require HTTP OAuth on stdio. Wrong audience/token forwarding or cross-owner access: Spoofing/Elevation of Privilege/Information Disclosure, CWE-287 or CWE-863 as applicable. |
| A proxy obtains downstream consent | Trace consent binding to user, client and scopes, including reuse and changed parameters. Cite the authorization entry and callback/state checks. | A generic login or prior consent for another client proves no current permission. Confused-deputy behavior: CWE-441, Elevation of Privilege. |
| Discovery, redirects or browser-accessible HTTP transport | Inspect destination validation at every outbound hop and allowed Origins on incoming HTTP, including loopback. Cite URL input, connection enforcement and receiving Origin handling. | Account for deployment egress enforcement and transport-specific applicability; absence from one source file is not proof. SSRF: CWE-918; cross-origin request acceptance: CWE-346, with a concrete attacker path. |
| Local stdio process launch | Inspect fixed executable/arguments, explicit approval of configuration-driven starts, credential environment and OS-enforced file/network access. Cite launcher and enforced restrictions. | Installed local binaries are not automatically unsafe; shell-free fixed commands are not injection. Attacker-selected command execution: CWE-78; excessive process privilege: CWE-250. |
| Tool descriptions or results influence subsequent actions | Trace descriptor/result provenance and the independent authorization of the final action. | MCP transport is not agent-to-agent communication by itself. ASI tags require a proven agentic mechanism; use ordinary STRIDE/CWE when no LLM is involved. |

Inspect actual configured transport and protocol revision. Map severity to the demonstrated protected resource, privilege and attacker reach, retaining normal caps and evidence rules. Unknown remote implementation remains a scoped verification gap. Test wrong audiences, forwarded tokens, cross-client consent, cross-owner handles, forbidden destinations and unsafe process inheritance only in synthetic local fixtures.
